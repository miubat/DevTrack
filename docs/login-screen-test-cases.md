**Where the expected results come from.** Only from written requirements: the SRS (FR-AUTH-01, 02, 04, §1.3, NFR-SEC-02, 05, 06), the parent AGL-05 acceptance criteria, each ticket's "Done when", and the BA validation comment on AGL-05.1. The build is never a source for an expected result. What the build shows goes in Actual Result. The build is only used to decide *how* to run a step (page addresses, test set-up).

Labels used in this file:

- **(BA, AGL-05.1)**: stated in the BA validation comment on AGL-05.1.
- **(inferred)**: not written in a requirement, taken from a related section or convention.
- **(design choice)**: no requirement covers it; this case states one sensible behaviour. Confirm with the BA (open questions below).
- **TBD**: no requirement says. Record what is seen in Actual Result.
- **Out of sprint scope**: the line needs a feature no Sprint 2 ticket builds. That line is Not run and is not raised as a bug.
- **(bug ticket BUG-AGL-…)**: no requirement covers this line, so QA 2 raised the expected behaviour as a bug in Bugs · AGL. The line is expected until the BA closes that bug as Not a bug; then the line goes back to the earlier expected result. The developer tasks stay "qa passed", because no SRS, ticket or BA line failed.
